# SDK 与 CLI 开发计划

本次目标：让用户安装 `pyrh56` 后，能直接完成串口发现、通信验证、反馈采集、诊断、基础控制和力标定。
命令名使用 `pyrh56`，与发行包保持一致；Python 导入名称继续为 `rh56_sdk`。

## 实施顺序与验收

- [x] **官方资料核对**：下载官网驱动，检查文件内容，对照 RH56 V1.09 手册。记录来源、摘要和支持边界；下载文件留在被忽略的 `.reference/`，不打包厂商代码。
- [x] **SDK 完善**：补配置与单指输入校验、硬件状态预检查、基于反馈的到位等待、串口信息与标定配置校验。保留既有接口；无效输入现在明确拒绝，新增行为有回归测试。
- [x] **CLI 开发**：用标准库 `argparse` 提供 `ports`、`ping`、`state`、`watch`、`doctor`、`move`、`finger`、`open`、`close`、`stop`、`speed`、`force`、`clear-error`、`calibrate`。提供 Mock、JSON/JSONL、稳定退出码与明确的设备选择。
- [x] **文档和构建验证**：中英文快速开始、完整命令说明、更新日志；运行 pytest、覆盖率、ruff、mypy，并验证构建产物中的入口在源码目录外可运行。版本为 0.4.0，尚未发布到 PyPI。
- [x] **首轮真机验证**：COM13 连续采集、SDK/CLI 小幅食指运动、零速响应与参数恢复；修复未知状态误报正常及单指命令受其他通道限位影响的问题。详见[真机测试报告](hardware-test-report.md)。

## 设计约束

- CLI 调用 SDK，不复制串口和协议实现；运行时仍只依赖 pyserial。
- 实机命令必须显式指定串口；串口枚举不等同于 RH56 设备发现。
- 运动前读取 STATUS/ERROR，避免每次启动的新进程丢失旧进程的故障标记。
- ACK 表示写寄存器成功；`--wait` 通过 ANGLE_ACT 判断到位，力控停止不当作角度到位。
- 单指 CLI 只写所选通道，不改写其他通道目标；未知状态警告不等同于已验证设备健康。
- `stop` 绕开连接时的角度同步，只尝试写入零速度并检查 ACK。它是通信指令，不能保证失联设备停止。
- 默认六通道范围为 0–1000；拇指 200–700 作为可选保守配置，旧的 200–1000 配置保留兼容。坐标是设备标度，不是角度单位。
- 标定需用户显式传入 `--confirm` 确认手为空载；只读诊断不触发运动或标定。
- Mock 保持现有零反馈语义，不宣称模拟运动或物理响应。

## 后续工作

已完成当前设备的空载食指及 1–5 手势验证；扩大真机验收范围后再考虑批量设备探测、动作序列、ROS 适配、可视化和 Agent skill。
验收应记录确切型号、左右手、固件、通信接口、串口适配器和系统，测试拔线、故障阻塞、停止后恢复速度、标定及到位超时。
